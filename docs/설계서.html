ShotFlow 설계서

AI 영상 제작을 위한 사내용 샷·버전·검수·납품 관리 툴

v0.6 · 3D 연동 반영2026-10-15상태: v1 구현 완료, 3D 연동 추가

1한 줄 정의

AI로 만든 샷을 등록 → 자동 검수 → 리뷰·승인 → 편집본 조립 → 납품까지 한 화면에서 관리하는 툴.

생성 설정(프롬프트·시드·모델·비용)은 자동으로 기록되어, 어떤 결과물이든 "어떻게 만들었는지" 추적할 수 있다.

2만드는 이유 (실제로 겪은 문제)

AI 제품 영상 3편(클립 16개, 960크레딧)을 만들면서 실제로 생긴 문제:

문제실제 사례ShotFlow 해결
버전 혼란같은 자료의 백업·"교체전"·"연결전" 파일이 수십 개. 어느 것이 최신인지 사람이 찾아야 함버전 관리
생성 기록 분산프롬프트·작업 ID·비용이 샷마다 JSON 파일 4~5개에 흩어짐 (Submission / Download / Ledger …)생성 기록 자동화
검수 누락향수 영상 R04→R05에서 배경이 비 장면 → 초록 스튜디오로 급변. 기술 검사는 통과했지만 컷 경계를 따로 보는 단계가 없었음자동 검수 + 경계 비교 시트
편집 재현편집 구간이 JSON과 별도 스크립트에 있어, 샷 하나 교체하려면 파일을 직접 고쳐야 함편집 자동 조립

4기능 명세

① 프로젝트 → 시퀀스 → 샷 → 버전 관리

  • 계층: Project(AI Product Films) → Sequence(BASALT RUN 등 영상 1편) → Shot(B01…) → Version(v01, retry01…)
  • 버전 상태: 대기 → 검토중 → 승인 / 반려 / 수정요청
  • 샷마다 현재 승인 버전 1개를 가리킴. 편집 조립은 이 값을 사용.
  • 원본 파일은 경로로만 참조하고 절대 수정하지 않음. 썸네일·프록시·필름스트립은 별도 캐시에 생성.

② 자동 검수 (QC)

버전이 등록되면 자동 실행. 결과는 타임코드 구간 + 심각도로 저장해 리뷰 화면 타임라인에 표시.

③ 리뷰 화면

  • 후보 2개 나란히 비교 (동기 재생, 프레임 단위 이동, 와이프 비교)
  • 타임라인 위에 QC 구간 표시, 클릭하면 해당 프레임으로 이동
  • 프레임 지정 코멘트, 승인/반려/수정요청 결정 (결정마다 작성자·시각 기록)

④ 편집본 자동 조립

  • 시퀀스마다 편집 결정 목록(EDL)을 보관: 샷 순서, 사용 버전, 시작/끝 프레임, 전환(컷/디졸브), 색 보정 값
  • 버튼 하나로 승인 버전들을 FFmpeg로 조립 → 결과물을 시퀀스의 새 버전으로 자동 등록 → 다시 자동 검수
  • 엔드카드(제품명 타이틀) 옵션
  • 같은 EDL이면 같은 결과가 나오도록 EDL을 결과와 함께 저장

⑤ ComfyUI 통합 — 생성·수정 엔진 핵심 기능

ComfyUI를 단순 "생성 버튼"이 아니라 툴 안에 녹아든 생성·수정 엔진으로 쓴다. 아티스트는 ComfyUI에서 노드를 짜고, ShotFlow는 그 노드 구조를 읽어 누구나 쓰기 쉬운 화면으로 바꿔 준다.

⑤-1 레시피: 노드 구조 → 사용하기 쉬운 화면

  • ComfyUI에서 만든 워크플로를 그대로 레시피로 등록 (API JSON + 화면용 JSON 둘 다 보관, 레시피 자체도 버전 관리)
  • 노드 제목을 SF:프롬프트, SF:강도처럼 붙이면 그 입력만 ShotFlow 화면에 폼으로 노출 (나머지 노드는 숨김) → 노드를 몰라도 사용 가능
  • ComfyUI의 /object_info로 각 입력의 종류·범위·기본값을 자동으로 읽어 슬라이더·선택상자 생성
  • 각 버전 화면에 "이 결과를 만든 노드 구조"를 그림으로 표시 (어떤 노드가 어떤 값이었는지)

⑤-2 생성 편의 기능

  • 변형 그리드: 시드 × 강도 × 프롬프트 조합을 한 번에 요청 (예: 4×3=12개) → 결과를 격자로 비교 → 고른 것만 버전으로 등록
  • 같은 설정으로 다시 실행: 버전마다 저장된 노드 구조·값·시드·모델 해시로 다시 생성. GPU 연산 특성상 픽셀 단위 동일은 보장되지 않으므로, 재실행 결과와 원본의 차이를 측정해 함께 기록
  • 값 하나만 바꿔 다시 실행: 기존 버전에서 시작해 원하는 입력만 바꿔 새 버전 생성 (버전 계보에 "어디서 무엇을 바꿨는지" 기록)

⑤-3 수정 루프 (리뷰 → 수정 → 재검토)

  • 리뷰 화면에서 프레임 위에 마스크를 직접 칠하고 수정 지시를 입력 → 인페인트 레시피 실행 → 수정 후보 여러 개 생성
  • 수정 후보는 원래 버전의 자식 버전으로 등록 (예: v01 → v01_fix_a / b / c) → 리뷰에서 원본과 나란히 비교 → 승인
  • 인페인트는 이미지 전체를 다시 인코딩하므로 마스크 밖도 미세하게 변한다 → 레시피 마지막에 ImageCompositeMasked로 원본을 다시 합성해 마스크 밖을 원본 그대로 유지
  • 그 뒤 마스크 밖 영역 픽셀 변화량을 자동 검사 (기준: 변화 0px, 초과 시 오류)
  • 버전 계보를 나무 모양으로 표시: 생성 → 수정 → FX 합성 흐름이 한눈에 보임

⑤-6 6GB GPU 대응

  • 동시 실행 1개, 작업이 끝나면 ComfyUI /free로 GPU 메모리 해제
  • 해상도 프리셋 (SD1.5 512~768, Wan 저해상도), 디코딩은 타일 방식
  • 메모리 부족 오류가 나면 자동으로 해상도를 낮추거나 타일 크기를 줄여 1회 재시도, 원인은 기록
  • 과거 실행 시간을 근거로 예상 소요 시간 표시 (실측값만 사용)
  • 실행 중 GPU 온도·VRAM·가용 RAM 감시: 온도 83°C 이상 / VRAM 98% 초과 / 가용 RAM 4GiB 미만이면 해당 작업만 중단 (기존 파이프라인에서 쓰던 기준 계승)
  • ComfyUI 실행/종료는 기존 manage_comfy.py를 호출 (기존 스크립트 수정 없음)
역할 분담: 이 PC의 성능상 고화질 최종 영상은 기존 Higgsfield 결과물이 맡고, ComfyUI는 키프레임·수정·변형과 파이프라인 구조를 보여 주는 데 집중한다.

10원칙

  1. 원본 불변: 기존 영상·기록은 읽기만 한다. 모든 산출물은 ShotFlow/data/에 생성.
  2. 기록 우선: 상태 변경·생성·조립·납품은 모두 누가·언제·무엇을 남긴다.
  3. 재현 가능: 편집은 EDL, 생성은 워크플로 원문+입력값으로 다시 만들 수 있게 저장.
  4. 측정한 것만 표시: 효율·시간 수치는 실제 로그에서 계산한 값만 화면과 문서에 쓴다.
  5. 로컬 전용: 서버는 127.0.0.1에서만 열린다. 외부 업로드 없음.
  6. 기존 환경 보호: 기존 제작_파이프라인, E:\AI_제작환경 스크립트는 수정하지 않는다. ShotFlow는 같은 ComfyUI 프로그램을 자기 전용 폴더(data/comfy)로 따로 실행한다 (D-003).

D결정기록 D-015 · 애니메틱 그림에서 Blender 블로킹 만들기

문제: 애니메틱(스토리보드 영상)에서 Blender 장면으로 넘어가는 단계가 손작업이었다. 영상마다 장면 스크립트를 따로 짜고, 그림과 카메라가 맞는지는 렌더를 보며 맞췄다. 어떤 그림을 보고 그 카메라를 정했는지도 남지 않았다.

결정: 반자동으로 한다. 컷 그림 위에 물체 상자와 수평선을 표시하고 렌즈를 고르면, 바닥이 평평하다는 가정 하나로 카메라 높이·기울기·거리와 대역 물체 위치를 계산한다(핀홀 카메라, 센서 폭 36mm).

  • 기울기 = atan((가운데 − 수평선) / 초점거리). 상자 아래 끝을 지나는 광선이 바닥과 만나는 곳이 물체 자리.
  • 물체 높이 = 카메라 높이 × (1 + gy · tz / ty) (g: 카메라 높이 1m일 때 바닥점, t: 상자 위 끝 광선). 실제 높이를 아는 물체 하나(기준 물체)가 카메라 높이를 정하고, 나머지 물체의 자리와 크기는 그림에서 나온다.
  • 떠 있는 물체(떨어지는 과일, 방울)는 기준 물체와 같은 거리에 둔다. 끝 그림을 표시하면 같은 기준 물체로 카메라를 한 번 더 풀어 컷의 첫·마지막 프레임에 키를 넣는다.

컷 경계는 D-002의 숨은 컷 규칙(한 프레임에서만 크게 바뀜)을 쓰되 최소 차이를 15 → 4로 낮췄다. 스토리보드 장은 머리글과 설명 글이 그대로라 실제 컷에서도 차이가 작았다(FIRST DROP v03: 컷 12.0과 14.6, 그 사이 0.3). 한 컷 안의 그림 여러 장은 겹치며 바뀌므로 컷으로 잡히지 않는다. 그림 영역은 어두운 장 위의 밝은 사각형으로 찾고, 테두리가 밝으면 화면 전체를 그림으로 본다. 제목 화면처럼 그림이 없는 컷은 빠진다.

Blender는 빈 장면에서 시작해 새 .blend만 저장한다(D-009의 "열기만 하고 저장하지 않음"은 그대로). 기준 물체는 원점, 표시한 물체는 회색 대역(병·사람·상자·둥근 물체·건물), 마스크 물체는 SF_MASK. 만든 파일은 장면 목록에 바로 올라가 3D 키프레임 단계(깊이·마스크 → ComfyUI)로 이어진다. 블로킹은 만들 때마다 lay_###로 쌓이고 표시 내용(marks)을 함께 남긴다.

버린 방법: 그림 한 장에서 깊이를 추정하는 모델 — 스케치 선 그림에서는 깊이가 안정적이지 않고, 결과가 물체가 아닌 굴곡진 면이라 블로킹으로 쓰기 어렵다. 그림 이해 AI가 상자를 제안하는 기능은 이 위에 얹을 수 있게 표시 형식(marks)을 맞춰 두었고, 아직 넣지 않았다.

검증: test_week9.py 13개. 알려진 카메라(높이 1.5m, 12° 아래, 35mm)로 찍은 상자를 거꾸로 풀면 높이·위치가 1% 안, 크기 2% 안. 실제 FIRST DROP v03 애니메틱: 컷 3개와 제목 화면을 정확히 나눔(무너지는 날 4컷도 같음). 손으로 만든 장면과 비교하면 A1은 카메라 높이 0.122m / 0.125m, 거리 0.63m / 0.70m, A3는 0.126m / 0.130m, 0.99m / 0.95m. A2는 그림 속 병이 실제 원근보다 작고 흐리게 그려져 있어 0.098m / 0.045m로 차이가 컸다. 블로킹은 그림을 그대로 따르므로, 그림과 실제 원근이 다르면 렌즈나 상자를 고쳐야 한다. Blender 블로킹 생성 3~4초, 그 파일로 깊이·마스크 패스 4.6초. 전체 105 / 105 통과.

찾은 버그: OpenCV의 imwrite는 Windows에서 한글이 들어간 경로에 오류 없이 저장에 실패한다. 이 데이터 폴더가 그렇다. 메모리에서 JPEG로 만든 뒤 파일로 쓰고, 한글 폴더에서 저장되는지 테스트를 추가했다.
